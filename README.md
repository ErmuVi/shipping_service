# Микросервис Службы Международной Доставки

Это асинхронный бэкенд-сервис для регистрации посылок, автоматического расчета стоимости их доставки и умной техподдержки пользователей (RAG-система).

## Технологический стек
* **Бэкенд:** Python 3.12, FastAPI, SQLAlchemy (асинхронный режим), Pydantic v2
* **Базы данных:** PostgreSQL (хранение данных), Qdrant (векторный поиск для ИИ), sqlite для тестов
* **Фоновые задачи и кэш:** Celery, Celery Beat, Redis
* **Контейнеризация:** Docker, Docker Compose

## Как устроен проект (Ключевые особенности)
1. **Сессии без авторизации:** Система отслеживает пользователей по уникальному `session_id` в HTTP-куках. У каждого анонимного пользователя свой изолированный список посылок.
2. **Фоновый расчет:** Раз в 5 минут сервис скачивает актуальный курс доллара с API Центробанка, кэширует его в Redis и рассчитывает стоимость доставки необработанных посылок.
3. **Умный помощник (RAG):** Система векторизует файл `knowledge_base.txt` с правилами таможни, ищет релевантные куски через Qdrant и отправляет контекст в LLM для точного ответа пользователю.

## Быстрый запуск (Docker Compose)

Проект полностью настроен и готов к запуску двумя командами из корня проекта.

### 1. Подготовка окружения
Убедитесь, что в корне проекта создан файл `.env` (на базе `.env.example`). Пример корректного файла:
```env
APP_TITLE="Shipping Service"
ENVIRONMENT=development
DEBUG=true
PORT=8000

DB_HOST=db
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=secret_password
DB_NAME=shipping_db

REDIS_HOST=redis
REDIS_PORT=6379

QDRANT_HOST=qdrant
QDRANT_PORT=6333

OPENROUTER_API_KEY=ваш_ключ_api
```

### 2. Сборка и запуск контейнеров
Запустите команду сборки образов (использует кэш для скорости):
```bash
docker compose build
```

Запустите всю систему (базы данных, веб-сервер и Celery поднимутся автоматически):
```bash
docker compose up
```

### 3. Применение миграций базы данных
В соседнем окне терминала запустите команду для создания таблиц в PostgreSQL:
```bash
docker compose run --rm web alembic upgrade head
```
*(Базовые типы посылок ("Одежда", "Электроника", "Разное") и векторная база знаний проиндексируются автоматически при первом старте сервера благодаря встроенному lifespan-обработчику).*

## Как проверить работу (Примеры роутов)

После запуска проект и интерактивная документация доступны по адресу: **http://localhost:8080/docs**

### Основные эндпоинты в Swagger:
* `GET /types` — Получить доступные типы посылок и их ID в базе данных.
* `POST /parcels` — Зарегистрировать посылку. На входе принимает JSON (Название, вес, стоимость в USD, ID типа). Валидирует данные и привязывает к вашей текущей куке сессии.
* `GET /parcels` — Посмотреть список своих посылок (с пагинацией и фильтрами по типам). Если стоимость еще не посчитана, выведет `"Не рассчитано"`.
* `POST /parcels/calculate-now` — Роут ручной отладки. Мгновенно запускает Celery-задачу для расчета стоимости посылок в рублях, не дожидаясь 5-минутного таймера.
* `POST /support/ask` — Задать вопрос техподдержке по правилам доставки (RAG-система).

### Пример вопроса для проверки ИИ-ассистента:
```json
{
  "question": "Можно ли отправить ноутбук?"
}
```

### Запуск тестов (Рекомендуемый способ в Docker)
Чтобы тесты успешно видели изолированные базы данных PostgreSQL и Qdrant, их необходимо запускать внутри контейнера `web`. 

1. Убедитесь, что контейнеры запущены в фоновом режиме:
```bash
docker compose up -d
```

2. Запустите прогон тестов с генерацией отчета о покрытии кода:
```bash
docker compose run --rm web pytest --cov=src --cov-report=term-missing
```
